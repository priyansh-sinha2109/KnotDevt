# KnotDevt PostgreSQL schema

Business resources belong to a project and inherit its workspace through
foreign keys. Login identities and sessions span a user's assigned
workspaces. The API connects as `knotdevt_app`, a non-owner PostgreSQL login
with neither superuser nor BYPASSRLS privileges. Alembic connects with the
local migration owner.

| Migration | Principal records |
| --- | --- |
| `0001_foundation` | Workspaces |
| `0002_auth` | Users, workspace and project memberships, signed session digests, audit events |
| `0003_imports` | Durable jobs, raw import payloads, sources, grants, source revisions, import results |
| `0004_evidence` | Claims, claim revisions, evidence links, claim relationships, agent runs, full-text index and row security |
| `0005_agents` | Frozen agent input and policy snapshot, stage budgets, checkpoint schema |
| `0006_handover` | Drafts, draft claims, immutable versions and version claims, approved rubrics, withdrawals |
| `0007_readiness` | Immutable readiness attempts, advisory jobs and reviewer feedback |
| `0008_receipts` | Independent receipts and immutable graph relationships |

A source identity is unique per project, provider, format and external ID.
A revision is unique per source and canonical SHA-256 content hash. Event
and ingestion times use timezone-aware columns. Original bytes live in
`import_jobs`. Source spans are Unicode code-point offsets into an exact
revision with an exclusive end. Reverse indexes on evidence links and claim
relationships support dependency lookup.

Claims use stable IDs and append-only revisions. Decisions, work, owners,
contacts, blockers, prerequisites and next actions are typed claim kinds.
Immutable versions link to exact claim revisions and store the approved
source revision and policy set. A content hash covers the snapshot and
rubric. Withdrawals, receipts and attempts have their own keys. PostgreSQL
triggers protect immutable records from updates and deletes.

RLS limits raw imports, source revisions, claim revisions and evidence links
to the project set with transaction-local `set_config`. Application queries
also check roles and source grants. A transaction ending clears that scope
even when the connection returns to the pool. LangGraph creates its own
checkpoint tables in the dedicated `agent_checkpoints` schema through
`scripts.setup_checkpoints`.
