# K0.1.0 API contracts

The local API exposes [Swagger UI](http://127.0.0.1:8080/docs) and
[OpenAPI JSON](http://127.0.0.1:8080/openapi.json). The inventory contains
39 operations across 34 paths. Resource IDs are UUIDs.

Use the session cookie returned by login. For authenticated writes, send
the returned `csrf_token` as `X-CSRF-Token`. Pagination uses `offset`,
`limit`, and `next_offset` on list resources. Authorization filters items
before pagination.

## Workflow details

- Imports take `application/json` up to 1 MiB. Issue batches use
  `kind: "issue-events"` and an `events` array. Conversation batches use
  `kind: "conversation-notes"` and a `notes` array. Both use `provider` and
  entries with source IDs, authors, event timestamps, references, exact text,
  event types, and optional related IDs and access policy. The API returns
  202 and a job ID. Use `Idempotency-Key` to repeat identical bytes safely.
  [Synthetic issue example](../../backend/tests/fixtures/issues.json) ·
  [Synthetic conversation example](../../backend/tests/fixtures/conversations.json)
- Agent jobs take `task`, `audience` and optional `source_ids`. Create the
  draft using the succeeded `agent_job_id`. A correction includes
  `draft_id`, `expected_revision`, `content` and `reason`. Approve using
  `expected_revision` and the reviewed `rubric`.
- Trace takes optional `version_id`. An assigned recipient supplies the
  approved version ID. The trace separates decision status, exact evidence
  and chronology, relationships, and unresolved items. Current draft trace
  requires an editor role and visible evidence.
- The version response includes the approved rubric ID. A readiness attempt
  takes an `answers` object keyed by `action`, `prerequisites`, `evidence`
  and `escalation` with zero-based choices. Optional fields are
  `client_attempt_id` and `explanation`. Repeating the same attempt key and
  answers returns the existing record. Receipt has no request body and
  repeats return the same timestamp.
- Errors use `code`, `message`, and `request_id`. Responses include
  `X-Request-ID`. Expect 401 for missing authentication, 403 for a denied
  operation, 404 for an invisible resource, 409 for stale state or a
  conflicting retry, 413 for an oversized import, 415 for a media-type
  mismatch, 422 for invalid input and 503 for unavailable dependencies.
