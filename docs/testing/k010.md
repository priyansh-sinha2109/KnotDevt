# Local testing and judge demonstration

Start the services using the [backend README](../../backend/README.md).
From `backend`, create and migrate the isolated local test database,
then run verification.

```powershell
uv sync --locked
uv run python -m scripts.setup_test_db
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run alembic check
uv run pytest -q
```

Tests use `knotdevt_test`, Redis logical DB 15, and the deterministic model
adapter. They cover HTTP contracts, role and source permissions, transaction
rollback, duplicate delivery, concurrent approval and receipt, checkpoint
resume, readiness gates, revocation, and the standalone worker import path.
Integration tests use a real PostgreSQL and Redis and run a Celery worker
where queue behavior is under test.

Run the complete synthetic workflow against the live loopback API, worker,
and scheduler.

```powershell
uv run python -m scripts.seed_demo
uv run python -m scripts.verify_local --project <printed-project-uuid>
```

For a repeated run, use `uv run python -m scripts.reset_demo` and pass its
new project UUID. The command checks the local database and exact synthetic
workspace membership, removes those three accounts' assignments from the
old demo workspace, and archives the workspace with its immutable history.
It then creates a fresh demo project. The scripts accept a prompted password
or `KNOTDEVT_DEMO_PASSWORD` in the ignored root `.env`.

With the local API ready, run the loopback health load test.

```powershell
k6 run --no-usage-report tests/load/health.js
```

The sample uses five virtual users for ten seconds and tests only the
liveness and readiness endpoints. The observed local results and live
Gemini verification status are in the [handover report](../backend-handover.md).
